## 4. Inference-Time Pipeline

This is the implemented path. It is fully tested and does **not** require any of the missing training-time files.

```
Caller supplies: a pandas DataFrame
  - Exactly 5 rows (oldest first, newest last)
  - 1 row per minute, exactly 60 seconds apart
  - Columns: [Timestamp (optional)] + 7 feature columns
  - Values: RAW, unscaled (do NOT pre-scale)
              │
              ▼
   predict_lstm.py → validate_window(window_df)
   ┌── Checks:
   │     MISSING_FEATURES   — all 7 feature columns present?
   │     BAD_SHAPE          — exactly 5 rows × 7 features?
   │     NAN_OR_INF         — no NaN or infinite values?
   │     NEGATIVE_VALUE     — no negative values?
   │     BOT_PCT_RANGE      — Bot_Pct ≤ 100 in all rows?
   │     BAD_TIMESTAMP      — Timestamp parseable? (if present)
   │     NOT_CONSECUTIVE    — rows exactly 60 s apart? (if Timestamp present)
   └── Raises InputValidationError with machine-readable .code if any check fails
              │
              ▼  (validation passed)
   Selects the 7 columns by name in fixed order
   Returns validated float array of shape (5, 7)
              │
              ▼
   scaler_features.transform(array_5x7)
   → scaled array, shape (1, 5, 7)
              │
              ▼
   Each of 5 seed models predicts:
     seed_42.predict(X_scaled) → raw output
     ...
     seed_46.predict(X_scaled) → raw output
              │
              ▼
   scaler_target.inverse_transform(each raw output)
   → 5 unscaled Bot_Pct predictions
              │
              ▼
   ensemble_pct = mean(5 seeds), clipped to [0, 100]
   predicted_state = Low (<25) / Medium (25–<50) / High (≥50)
   seed_spread_pct_points = max(5 seeds) − min(5 seeds)
              │
              ▼
   Return output dict (JSON-serialisable):
     forecast_horizon_minutes, predicted_bot_pct_next_minute,
     predicted_state, state_thresholds, seed_predictions,
     seed_spread_pct_points, model_version, model_status, warnings
```

### What the caller must supply

| Requirement | Detail |
|-------------|--------|
| Window size | Exactly 5 rows; no more, no fewer |
| Row ordering | Oldest row first (index 0), newest row last (index 4) |
| Spacing | Exactly 60 seconds between consecutive rows |
| Gap rule | Window must not span a data gap; if input data has gaps, the caller must split segments first |
| Feature values | Raw, unscaled; the module applies `scaler_features.transform` internally |
| Feature columns | Must be present by name: `Bot_Pct`, `Total_Flows`, `Fwd_Pkts_Bot`, `Bwd_Pkts_Bot`, `Fwd_Bytes_Bot`, `Bwd_Bytes_Bot`, `Avg_Duration_Bot` |
| `Timestamp` column | Optional but strongly recommended; enables the 60-second-spacing check |

> [!CAUTION]
> Never pre-scale the input before passing it to `predict_next_minute()`.
> The module calls `scaler_features.transform()` internally using the saved scaler.
> Pre-scaling would apply the transformation twice and produce wrong predictions silently.

## 6. Critical Data Notes

### The 207-minute gap

The dataset contains exactly **one gap** in the per-minute time series:

| Property | Value |
|----------|-------|
| Gap location | Between row 259 (timestamp ~05:29) and row 260 (timestamp ~08:56) |
| Gap duration | Approximately 207 minutes |
| Segments | Segment 0: rows 0–259; Segment 1: rows 260–502 |
| Rule | **No inference window may span this gap.** A window touching both segments is invalid. |

> [!CAUTION]
> At inference time it is the **caller's responsibility** to check for gaps before assembling
> windows. The backend module checks for 60-second spacing only if a `Timestamp` column is
> present. Without timestamps it cannot detect a gap.

### Row 259 — invalidated target

Row 259 (timestamp ~05:29) is the last row of Segment 0. Its `Target_Bot_Pct` was computed
by a naive `.shift(-1)` across the gap: it points to row 260 (timestamp ~08:56), not to the
true next minute. The notebook detected this, confirmed the cross-gap artefact, and **excluded
row 259 from all training targets**. The target scaler was fitted with row 259 excluded.

### Row 502 — unverified provenance

Row 502 (timestamp ~12:59) is the last row of the dataset. Its `Target_Bot_Pct` has
**unverified provenance**: no row at 12:59+1min exists in the on-disk files. The notebook
retained this row per the frozen protocol (`KEEP_LAST_ROW_TARGET = True`). This is noted in
`config.json` and in the ML Integration Contract. The test set therefore has **102 valid targets**
rather than 101 — but row 502's target is flagged as potentially unreliable.

### Train/test boundary policy

`BOUNDARY_POLICY = "context_allowed"` means that a sequence whose **context window** (the 5
input rows) overlaps the train/test boundary is still included, as long as its **target** falls
in the correct split. This is the standard policy for temporal LSTM forecasting.

### Autocorrelation evidence (from notebook config)

The notebook recorded autocorrelation of `Bot_Pct` to justify the LSTM approach:

| Lag (minutes) | Autocorrelation |
|----------------|----------------|
| 1 | 0.9022 |
| 5 | 0.8195 |
| 10 | 0.7322 |
| 15 | 0.6526 |

High autocorrelation supports using a 5-minute window (L=5) to predict the next minute.
